# Repository Guidelines

## Project Structure

PasswMana is a client-only offline-first PWA built with **Vite + React 19 + TypeScript + Tailwind CSS v4 + Amicro (`motion/react` + `lucide-react`)**.

- `index.html`: App shell entry with strict Content Security Policy.
- `public/`: Static PWA files (`manifest.webmanifest`, `icon.svg`, `sw.js`).
- `src/core/`: Pure TypeScript cryptography, IndexedDB persistence (`vault-core.ts`), 3-way sync merge (`sync-core.ts`), formatting/clipboard helpers (`ui-helpers.ts`), and reactive store (`vault-store.ts`).
- `src/components/amicro/`: Amicro-compatible Motion micro-interaction primitives (`AmicroButton`, `AmicroCopyButton`, `AmicroFavoriteButton`, `AmicroSwitch`, `AmicroSurface`, `AmicroDialog`, `AmicroToastStack`).
- `src/components/`: Feature views (`LockScreens`, `Sidebar`, `VaultWorkbench`, `SettingsView`, `Modals`, `FormHelpers`).
- `dist/`: Production static bundle generated by `npm run build` (including hashed `dist/sw.js`).

Do not add server-side code or put encrypted vault data in this repository.

## Local Development

```powershell
npm install
npm run dev       # Vite dev server
npm run build     # Build dist/ and generate dist/sw.js SHA-256 shell hashes
npm run preview   # Serve dist/ over localhost HTTP for SW & offline checks
```

Open the reported `http://localhost:...` URL, not `file://`, when checking service worker and install behavior.

## Coding Style

Use strict TypeScript and modern React functional components with four-space indentation and semicolons. Keep cryptographic and IndexedDB helpers pure in `src/core/`; keep UI components under `src/components/`. Use CSS custom properties (`src/index.css`) for colors so Appearance controls affect every view, and avoid inline `<style>` injection so strict `style-src 'self'` CSP remains intact. Prefer `lucide-react` icons rather than emoji or bespoke SVGs.

## Testing

```powershell
npm run typecheck
npm test
npm run test:browser
npm run test:pwa
```

Test both desktop and narrow mobile viewports. Cover first-run recovery key display, master-password unlock failure, auto-lock, entry CRUD, trash restore, encrypted backup import/export, legacy JSON migration, theme persistence, and manual sync failure states. Never use real passwords, recovery keys, or GitHub tokens in fixtures or commits.

## Commits and Pull Requests

Use concise imperative commit subjects, such as `Add encrypted backup export`. Keep each commit focused. PRs should describe user-visible changes, list verification performed, link relevant issues, and include desktop/mobile screenshots for UI changes.
